# RudeAuth C++ SDK

Licensing for Windows software. C++17, static library, no package manager and no external
dependency to resolve — the crypto is vendored and the transport is WinHTTP.

Every response from the server is Ed25519-signed, and the public key that verifies it is compiled
into your binary. A patched server, a proxy, or a hosts-file redirect cannot fake a successful
licence check.

- **API reference:** https://docs.rudeauth.com
- **Dashboard:** https://app.rudeauth.com/dash/

Paste this into Claude Code, Cursor, or any LLM.

```
My app id is <APP_ID> and my public key is <PUBLIC_KEY>.
```

## Quickstart

Five steps from nothing to a working licence check.

**1. Create an application.** Sign in at [app.rudeauth.com](https://app.rudeauth.com/dash/), open
**Applications**, create one. It is issued its own Ed25519 signing keypair. Copy the **application
ID** and the **public key** — both are safe to embed, and neither is a secret.

**2. Generate a licence key.** **Licences -> Generate.** Choose how many, how many days they last
(0 for perpetual), and how many devices each key may bind to.

Keys are shown once. Only a peppered hash is stored, so nobody — including you — can read them
back afterwards. Export the batch before leaving the page.

**3. Build the SDK.**

```
git clone https://github.com/Rudevin17/rudeauth-cpp.git
cd rudeauth-cpp
cmake -B build -S .
cmake --build build --config Release
```

**4. Try the example.** Copy `example/rudeauth.example.ini` to `rudeauth.ini` beside the binary,
fill in the values, and run `build/rudeauth_example.exe`:

```ini
RUDEAUTH_APP_ID=your-application-id
RUDEAUTH_PUBLIC_KEY=your-public-key
RUDEAUTH_BASE_URL=https://api.rudeauth.com
```

The example reads these from a file so it runs without a rebuild. A real client compiles them in —
see [How to use this wrongly](#how-to-use-this-wrongly).

**5. Integrate.**

```cpp
#include <rudeauth/rudeauth.hpp>

// Compiled in, not read from a file. A public key in a config file can be
// swapped for an attacker's, after which every signature check passes against
// a server they control.
constexpr auto APP_ID = "your-application-id";
constexpr auto PUBKEY = "your-public-key";

rudeauth::Client client(APP_ID, PUBKEY, "https://api.rudeauth.com");

auto auth = client.authenticate(user_entered_key);
if (!auth.ok()) {
    show(rudeauth::to_string(auth.error()));   // expired != device limit != banned
    return 1;
}
auto session = auth.value();                   // keep alive for the program's lifetime

auto core   = session->file("core.dll");       // never shipped inside your binary
auto offset = session->variable("offset");     // server-side, rotatable
```

In CMake:

```cmake
add_subdirectory(rudeauth-cpp)
target_link_libraries(yourapp PRIVATE rudeauth)
```

## Building

**CMake (MSVC or MinGW):**

```
cmake -B build -S .
cmake --build build --config Release
```

Then link `rudeauth` and add `include/` to your include path.

**Directly with MinGW:**

```
g++ -std=c++17 -O2 -c src/*.cpp -Iinclude -Isrc
gcc -std=c99 -O2 -c src/vendor/*.c -Isrc/vendor
ar rcs librudeauth.a *.o
```

Link with `-lwinhttp -ladvapi32 -lbcrypt`.

> **Verification status.** Built and tested on both toolchains:
>
> | Toolchain | Build | Known-answer tests | Live protocol |
> |---|---|---|---|
> | MSVC 17.14.51 (VS 2022, v143) | ✅ | ✅ 23/23 | — |
> | MinGW-w64 GCC 16.2.0 | ✅ | ✅ 23/23 | ✅ 13/13 |
>
> The known-answer tests are the ones that matter across compilers: they check this library's
> crypto against vectors generated by the server's own code, so a compiler difference cannot pass
> silently.

## What the API deliberately does not have

There is no function returning a bool that means "is this user licensed."

A boolean is one byte in memory and one branch in the disassembly. `authenticate()` returns a
`Session` or an error, and the gating calls exist only on a `Session` — which cannot be
constructed without a response signature that verified against the key compiled into your binary.

`Result::ok()` reports whether the *call* succeeded. A rejected licence is `ok() == false` with a
specific `Error`.

## How to use this wrongly

Three real failure modes, in the order people hit them:

**1. Fetching the payload and not using it.** If your program runs fine without `core.dll`, an
attacker deletes the call and ships. Gating only works when the program genuinely cannot function
without what the server sends. Move real logic into the payload, not a splash screen.

**2. Hardcoding a variable "just for testing".** It ships. A variable is protection only while it
changes faster than someone will maintain a patch; a constant delivered over the network is
convenience. Rotate anything you rely on.

**3. Wrapping the SDK in `bool is_licensed()`.** This is the most common and the most damaging —
it reintroduces exactly the patch target the API was shaped to remove. If you find yourself
writing that helper, the design has been undone. Pass the `Session` to the code that needs it.

## Behaviour worth knowing

- **No offline mode, no cache.** If the server is unreachable, calls fail. A cached "last known
  good" state is precisely what an attacker induces by blocking the network.
- **A missed heartbeat is not a logout.** The session retries until its TTL genuinely lapses, so a
  three-second network blip does not drop a paying customer.
- **On a one-session licence, relaunching supersedes the older session.** That is what "one
  session" means. Raise `max_concurrent_sessions` if your product runs two instances.
- **Fewer than two readable hardware components and the SDK refuses to authenticate**, rather than
  sending a weak identity the server would have to accept.
- **Fingerprints are forgeable.** Device binding deters casual licence sharing. It is not a
  control against a motivated attacker and should not be described as one.

## Errors

| Error | Meaning |
|---|---|
| `Network` | server unreachable |
| `SignatureInvalid` | **the responder is not holding your application's key** |
| `NonceMismatch` | a replayed response |
| `ClockSkew` | this machine's clock is too far off |
| `LicenseInvalid` | unknown, revoked or banned — deliberately indistinguishable |
| `LicenseExpired` | user-actionable |
| `DeviceLimit` | licence is bound to its maximum machines |
| `DeviceBlacklisted` | this hardware is banned |
| `SessionExpired` | re-authenticate |
| `RateLimited` | back off |

## Vendored code

Monocypher 4.0.3 (public domain / CC0), in `src/vendor/`. Both `monocypher` and
`monocypher-ed25519` are required: the default EdDSA is BLAKE2b-based and would reject every
signature the server produces. `tests/crypto_test.cpp` exists mainly to catch that, using known
answers generated by the server itself.
